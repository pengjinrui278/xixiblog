## 一、决策树与比较排序下界（§8.1）

### 【定义】比较排序

> **原文摘录**（§8.1，此 PDF p.284）
> "A comparison sort uses only comparisons between elements to gain order information about an input sequence $\langle a_1, a_2, \dots, a_n\rangle$."

比较排序只允许通过 $a_i \le a_j$ 这类测试获取顺序信息，**不许偷看元素的值**。我们至今学过的插入、归并、堆、快速排序全是比较排序。

### 【定义】决策树模型

**决策树**是一棵满二叉树：每个内部节点标注 $i:j$（一次比较 $a_i \le a_j$），每个叶子标注一个排列 $\langle\pi(1),\pi(2),\dots,\pi(n)\rangle$（表示 $a_{\pi(1)} \le a_{\pi(2)} \le \cdots \le a_{\pi(n)}$）。算法执行 = 从根到某叶子的一条路径（§8.1，此 PDF p.285-286）。

**关键观察**：
- 正确性要求 $n!$ 个排列每个都至少对应一个**可达**叶子 → 叶子数 $l \ge n!$；
- 高为 $h$ 的二叉树最多 $2^h$ 个叶子；
- 根到叶最长路径 = 最坏情况比较次数 = 树高。

### 【定理 8.1】任何比较排序最坏情况需要 $\Omega(n\lg n)$ 次比较

**证明**：设决策树高 $h$、可达叶子 $l$。由 $n! \le l \le 2^h$ 取对数得
$$h \ge \lg(n!) = \Omega(n\lg n)$$
（用 Stirling 式 (3.28)）。（§8.1，此 PDF p.287）

### 【推论 8.2】堆排序与归并排序是渐近最优的比较排序

它们的 $O(n\lg n)$ 上界与下界吻合（§8.1，此 PDF p.287）。

### 【例题 8.1-1】决策树叶子的最小可能深度是多少？

**解**：$\lceil \lg n!\rceil$（当树完全平衡时取到）。注意**平均**比较次数对应叶子的平均深度，可低至 $\Theta(\lg n!)$；而最坏情况由树高决定。这也是"某些输入快、某些输入慢"的结构根源。

### 【思考】下界为什么能被绕开？

因为下界只约束"靠比较获取信息"的算法。下面三个算法**直接利用元素的值本身**来定位——一旦允许数数、索引、求模，信息论下界就不适用了。

## 二、计数排序：不比较，只数数（§8.2）

### 【定义】计数排序

> **原文摘录**（§8.2，此 PDF p.288）
> "Counting sort assumes that each of the $n$ input elements is an integer in the range 0 to $k$, for some integer $k$. It runs in $\Theta(n+k)$ time, so that when $k = O(n)$, counting sort runs in $\Theta(n)$ time."

核心思想：先数出每个值出现了几次，再求出"小于等于 $x$ 的元素有多少"，直接把 $x$ **放到它该在的位置**。书中的例子很传神：如果 17 个元素 $\le x$，那 $x$ 就该住进输出位置 17。

### 【伪代码】COUNTING-SORT

```
// file: COUNTING-SORT（§8.2，此 PDF p.289）
COUNTING-SORT(A, n, k)
 1  let B[1 : n] and C[0 : k] be new arrays
 2  for i = 0 to k                    // C 清零
 3      C[i] = 0
 4  for j = 1 to n                    // 第一遍：数数
 5      C[A[j]] = C[A[j]] + 1         // C[i] = 值等于 i 的元素个数
 6  for i = 1 to k                    // 前缀和
 7      C[i] = C[i] + C[i - 1]        // C[i] = 小于等于 i 的元素个数
 8  for j = n downto 1                // 第二遍：倒序放置
 9      B[C[A[j]]] = A[j]
10      C[A[j]] = C[A[j]] - 1         // 相同值的元素往前排一位
11 return B
```

### 【三个细节】

1. **为什么要倒序扫 $A$（第 8 行 downto）**：正序放也能对，但会**破坏稳定性**——相同值的元素在输出中顺序被颠倒。倒序 + 放置后 $C$ 递减，保证相同值元素按输入先后落位（§8.2，此 PDF p.291-292，Ex 8.2-3）。
2. **稳定性（stable）**：相同值元素在输出中保持输入时的相对次序。计数排序稳定，这是它能当基数排序"内功"的前提。
3. **复杂度**：四个循环分别是 $\Theta(k)+\Theta(n)+\Theta(k)+\Theta(n) = \Theta(n+k)$。当 $k=O(n)$ 时线性。

### 【例题 8.2-1】逐步演算

对 $A=\langle 6, 0, 2, 0, 1, 3, 4, 6, 1, 3, 2\rangle$（$n=11, k=6$）运行 COUNTING-SORT：

| 步骤 | $C[0..6]$ |
|---|---|
| 数数后（第 5 行） | 2, 2, 2, 2, 1, 0, 2 |
| 前缀和后（第 7 行） | 2, 4, 6, 8, 9, 9, 11 |
| 放置 $A[11]=2$ 后 | 2, 4, **5**, 8, 9, 9, 11 |
| 放置 $A[10]=3$ 后 | 2, 4, 5, **7**, 9, 9, 11 |
| … | … |

最终 $B=\langle 0, 0, 1, 1, 2, 2, 3, 3, 4, 6, 6\rangle$。注意两个 0 在输入中先后出现（位置 2、4），输出中仍是位置 2 的在前——稳定性的直观体现。

### 【例题 8.2-4】★ 循环不变式（书中习题）

> 第 8-10 行循环每次迭代开始时，$A$ 中尚未拷入 $B$ 的、最后一个值为 $i$ 的元素属于 $B[C[i]]$。

**证明**：
- **初始化**：第一次迭代前 $C[i]$ 恰为"值 $\le i$ 且排在最后一个 $i$ 之后（含自己）的元素总数"，即最后一个 $i$ 的正确位置。
- **保持**：放置一个值为 $v$ 的元素后 $C[v]$ 减 1。若 $i=v$，下一个尚未放置的 $v$ 的正确位置恰是刚放置位置的前一位，与新的 $C[v]$ 一致；若 $i\ne v$，值 $i$ 的最后未放置元素的位置没变，$C[i]$ 也没动。
- **终止**：循环结束时所有元素已放置，不变式自然成立。

### 【拓展】原地计数排序（Ex 8.2-5）

若没有卫星数据要搬，可以只用 $A$ 和 $C$：先数数，然后按 $C$ 的前缀和信息把 $A$ 中元素**循环换位**到最终位置（类似循环排序，$O(n+k)$ 时间、$O(k)$ 额外空间）。但这样写**不再稳定**——循环换位不保证相同值相对次序。

## 三、基数排序：从最低位开始（§8.3）

### 【直觉】为什么从 LSD（最低位）开始

你可能会想：先按最高位排，再递归排每个桶。但那样要同时维护大量中间堆。基数排序反其道而行——**先按最低位排，再按次低位排……最后按最高位排**。每一遍必须用**稳定排序**，这样低位的成果才不会被高位破坏。

> **原文摘录**（§8.3，此 PDF p.293）
> "Radix sort solves the problem of card sorting—counterintuitively—by sorting on the least significant digit first."

### 【图示】三位数的三遍排序

输入 $\langle 329, 457, 657, 839, 436, 720, 355\rangle$（§8.3，此 PDF p.293，Figure 8.3）：

```
输入:  329  457  657  839  436  720  355
第1遍(个位): 720  329  436  839  457  355  657
第2遍(十位): 720  329  436  839  457  355  657
第3遍(百位): 329  355  436  457  657  720  839
```

（第 1 遍按个位分桶：0→720；2→329；6→436, 457, 355, 657 按**输入顺序**——稳定性保证 436 在 457 前、355 在 657 前……最终整体有序。）

### 【伪代码】RADIX-SORT

```
// file: RADIX-SORT（§8.3，此 PDF p.294）
RADIX-SORT(A, n, d)
 1  for i = 1 to d          // digit 1 是最低位
 2      use a stable sort to sort array A[1 : n] on digit i
```

### 【引理 8.3】$n$ 个 $d$ 位数、每位 $k$ 种取值，稳定排序耗时 $\Theta(n+k)$，则 RADIX-SORT 耗时 $\Theta(d(n+k))$

**证明**：正确性对"已排好的位数"归纳（Ex 8.3-3）：假设前 $i-1$ 个低位已就序，第 $i$ 遍稳定排序后，所有低 $i$ 位有序。时间复杂度显然：$d$ 遍 × 每遍 $\Theta(n+k)$。（§8.3，此 PDF p.294-295）

### 【引理 8.4】位数分解的自由度

$n$ 个 $b$ 位数，任取 $r \le b$，视为 $d=\lceil b/r\rceil$ 个 $r$ 位数字，则时间 $\Theta((b/r)(n+2^r))$。

**证明**：每位数域 $[0, 2^r)$，用计数排序 $k=2^r-1$；$d$ 遍相乘即得。（§8.3，此 PDF p.295）

### 【怎么选 $r$】一个经典的两难

$(b/r)(n+2^r)$ 中，$r$ 小则 $b/r$ 大，$r$ 大则 $2^r$ 大。最优解（§8.3，此 PDF p.295-296）：
- 若 $b < \lfloor \lg n\rfloor$：取 $r=b$，时间 $\Theta(n)$——**渐近最优**；
- 若 $b \ge \lfloor \lg n\rfloor$：取 $r=\lg n$，时间 $\Theta(bn/\lg n)$。

**常见误区**：$b=O(\lg n)$ 时基数排序 $\Theta(n)$ "完爆"快排的 $\Theta(n\lg n)$？书里明确提醒：$\Theta$ 记号**藏着常数因子**。基数排序每趟要扫描 + 分配 + 收集，一趟可能比快排一整层分治还贵；且基数排序**不原地**。实际选谁取决于实现、机器缓存特性（快排通常更友好）和内存压力。

### 【例题 8.3-2】哪些排序稳定？

插入、归并稳定；堆、快排**不稳定**。让任意比较排序变稳定的标准办法：给每个元素带上原始下标，比较时"键相同比下标"，等价于键全相异。代价 $\Theta(n)$ 额外空间、每个元素比较时多一步判断。

### 【例题 8.3-5】$[0, n^3-1]$ 的整数 $O(n)$ 排序

把 $3\lg n$ 位二进制视为 3 个"数字"，每个 $\lg n$ 位。则 $b=3\lg n \ge \lg n$，由引理 8.4 取 $r=\lg n$：时间 $\Theta((3\lg n/\lg n)(n+2^{\lg n})) = \Theta(3(n+n)) = \Theta(n)$。

## 四、桶排序：把均匀分布变成免费午餐（§8.4）

### 【定义】桶排序

> **原文摘录**（§8.4，此 PDF p.297）
> "Bucket sort assumes that the input is drawn from a uniform distribution and has an average-case running time of $O(n)$."

把 $[0,1)$ 切成 $n$ 个等宽桶，第 $i$ 个桶装 $[i/n, (i+1)/n)$ 里的数。均匀分布下每桶期望 $O(1)$ 个元素，桶内插入排序加起来期望 $O(n)$，最后按桶序拼接。

### 【伪代码】BUCKET-SORT

```
// file: BUCKET-SORT（§8.4，此 PDF p.298）
BUCKET-SORT(A, n)
 1  let B[0 : n - 1] be a new array
 2  for i = 0 to n - 1
 3      make B[i] an empty list
 4  for i = 1 to n
 5      insert A[i] into list B[⌊n · A[i]⌋]
 6  for i = 0 to n - 1
 7      sort list B[i] with insertion sort
 8  concatenate the lists B[0], B[1], …, B[n - 1] together in order
 9  return the concatenated lists
```

**正确性**：$A[i]\le A[j]$ 时 $\lfloor nA[i]\rfloor \le \lfloor nA[j]\rfloor$，同桶由第 7 行纠正次序，不同桶由第 8 行保证次序。

### 【分析】期望线性的完整推导

设 $n_i$ = 第 $i$ 桶的元素数。总运行时间（§8.4，此 PDF p.299）：
$$T(n) = \Theta(n) + \sum_{i=0}^{n-1} O(n_i^2)$$

**第一步**：$n_i$ 是 $n$ 重 Bernoulli 试验的成功次数（每次成功概率 $p=1/n$）。由附录 C（此 PDF p.1199-1200）：
$$E[n_i] = np = 1,\qquad E[n_i^2] = \mathrm{Var}[n_i] + E^2[n_i] = npq + n^2p^2 = 2 - \frac{1}{n}$$

**第二步**：代入并用期望线性性：
$$E[T(n)] = \Theta(n) + \sum_i O\big(E[n_i^2]\big) = \Theta(n) + n\cdot O(2 - 1/n) = \Theta(n)$$

**最坏情况是 $\Theta(n^2)$**（全进一个桶）。Ex 8.4-2 的修正：桶内改用 $\Theta(n_i\lg n_i)$ 的归并排序，保期望线性、最坏 $O(n\lg n)$。

### 【例题 8.4-3】$E[X^2]$ 与 $E^2[X]$

$X$ = 抛两次均匀硬币正面数。$P(X{=}0)=1/4, P(X{=}1)=1/2, P(X{=}2)=1/4$：
$$E[X] = 1/2,\qquad E[X^2] = 0\cdot\tfrac14 + 1\cdot\tfrac12 + 4\cdot\tfrac14 = \tfrac32,\qquad E^2[X] = \tfrac14$$
所以 $E[X^2] \ne E^2[X]$——**矩与矩的平方是两回事**，桶排序分析里 $E[n_i^2]$ 不能偷换成 $E^2[n_i]=1$。

## 五、最小值、最大值与锦标赛论证（§9.1）

### 【问题】选择问题（selection）

> **原文摘录**（§9，此 PDF p.312）
> "The $i$th order statistic of a set of $n$ elements is the $i$th smallest element."

输入 $n$ 个互异数和 $i$，输出恰好比 $i-1$ 个元素大的那个。最小 = 第 1 个，最大 = 第 $n$ 个；本书"中位数"专指**下中位数** $\lfloor (n+1)/2\rfloor$。

### 【最小值的下界】为什么必须 $n-1$ 次比较

> **原文摘录**（§9.1，此 PDF p.313）
> "Think of any algorithm that determines the minimum as a tournament among the elements. Each comparison is a match in the tournament in which the smaller of the two elements wins. Since every element except the winner must lose at least one match, we can conclude that $n-1$ comparisons are necessary."

**锦标赛论证**：每次比较是一场"较小的赢"的比赛。除冠军外每个元素至少输一场 → 至少 $n-1 场比赛。一行一个的 MINIMUM 恰好 $n-1 次，**最优**。

### 【同时找最小和最大】$3\lfloor n/2\rfloor$ 次

逐个元素跟当前 min、max 各比一次要 $2n-2$ 次。技巧：**成对处理**（§9.1，此 PDF p.314）——先比一对内部大小（1 次），小的跟 min 比、大的跟 max 比（2 次），每 2 个元素 3 次比较：

| $n$ 奇偶 | 初始化 | 总数 |
|---|---|---|
| $n$ 奇 | min=max=$A[1]$ | $3\lfloor n/2\rfloor$ |
| $n$ 偶 | 先比 $A[1],A[2]$ 定初值 | $1 + 3(n-2)/2 = 3n/2 - 2$ |

### 【例题 9.1-1】第二小：$n + \lceil \lg n\rceil - 2$ 次

**解**：第二小只可能输给过最小值。先用 $n-1$ 次锦标赛找出最小（顺便记录每个元素的"败绩列表"），最小值赢过的元素构成候选集，只有冠军的"直接手下"才可能第二小。把锦标赛组织成平衡二叉树，冠军手下共 $\lceil \lg n\rceil$ 人，在其中找最小要 $\lceil \lg n\rceil - 1$ 次。总计 $n-1+\lceil\lg n\rceil-1$。

### 【例题 9.1-4】★ $\lceil 3n/2\rceil - 2$ 下界（书中习题）

**提示思路**（书中给提示）：把元素分成四类——必是最小候选、必是最大候选、两者皆非、两者皆可能。一次比较最多让 2 个"两者皆可能"的元素各消去一个身份。$n$ 个元素初始 $2n$ 个待消身份，最终剩 2 个（一个最小一个最大），故至少 $(2n-2)/2 = n-1$ 次；更精细的计数给出 $\lceil 3n/2\rceil - 2$。

## 六、RANDOMIZED-SELECT：只递归一边的艺术（§9.2）

### 【核心观察】

快速排序递归处理分区**两侧**，所以 $\Theta(n\lg n)$；选择问题只需要**一侧**——这个差异就是线性期望时间的全部来源。

> **原文摘录**（§9.2，此 PDF p.315）
> "Whereas quicksort has an expected running time of $\Theta(n\lg n)$, the expected running time of RANDOMIZED-SELECT is $\Theta(n)$, assuming that the elements are distinct."

### 【伪代码】RANDOMIZED-SELECT

```
// file: RANDOMIZED-SELECT（§9.2，此 PDF p.316）
RANDOMIZED-SELECT(A, p, r, i)
 1  if p == r
 2      return A[p]        // 只剩一个元素时必有 i = 1
 3  q = RANDOMIZED-PARTITION(A, p, r)
 4  k = q - p + 1          // 低区元素数 + 1（含枢轴）
 5  if i == k
 6      return A[q]        // 枢轴就是答案
 7  elseif i < k
 8      return RANDOMIZED-SELECT(A, p, q - 1, i)
 9  else return RANDOMIZED-SELECT(A, q + 1, r, i - k)
```

第 9 行的 $i-k$ 是关键：高区里比目标小的元素已经有 $k$ 个，目标变成高区里的第 $i-k$ 小。

### 【最坏情况】$\Theta(n^2)$

运气差到每次都拿最大元素当枢轴，每步只排除枢轴一个元素：$T(n) = T(n-1) + \Theta(n) = \Theta(n^2)$（§9.2，此 PDF p.318）。但它是随机化算法——**没有任何特定输入能触发的期望最坏**。

### 【有益划分】定义与引理

**有益划分（helpful partitioning）**：第 $j$ 次划分后仍在游戏中的元素集 $A^{(j)}$ 满足 $|A^{(j)}| \le \tfrac34 |A^{(j-1)}|$。

> **引理 9.1**：一次划分有益的**概率至少 1/2**。
> **证明**（§9.2，此 PDF p.319-320）：枢轴落在"中间一半"（去掉最小 $\lceil n/4\rceil-1$ 和最大 $\lceil n/4\rceil-1$ 个元素）时必有益——无论目标在哪侧，至少 $\lceil n/4\rceil$ 个元素出局，剩余 $\le \lfloor 3n/4\rfloor$。枢轴落在中间一半的概率至少 $1 - \frac{2(\lceil n/4\rceil-1)}{n} \ge \frac12$。

### 【定理 9.2】RANDOMIZED-SELECT 期望时间 $\Theta(n)$

**证明结构**（§9.2，此 PDF p.320-323，本书概率分析最精巧的证明之一）：

1. 有益的划分按序编号 $h_0=0 < h_1 < \cdots < h_m$。最多 $\lceil \log_{4/3} n\rceil$ 次有益划分后只剩 1 个元素，故 $n_k = |A^{(h_k)}| \le (3/4)^k n_0$。
2. 把划分数列按有益划分切成 $m$ 个**代（generation）**，第 $k$ 代从 $A^{(h_k)}$ 开始到下一个有益划分前结束。
3. 设 $X_k$ = 第 $k$ 代的划分数。每次划分有益概率 $\ge 1/2$（几何分布），故 $E[X_k] \le 2$。
4. 第 $j$ 次划分的比较次数 $< |A^{(j-1)}|$，总比较次数：
$$\sum_{k=0}^{m} X_k \cdot n_k$$
（一代内每步规模 $\le n_k$，共 $X_k$ 步）
5. 取期望：$\sum_k E[X_k]\cdot n_k \le \sum_k 2(3/4)^k n_0 = O(n_0)$。
6. 下界：第一次 PARTITION 就要看全部 $n$ 个元素，$\Omega(n)$。合起来 $\Theta(n)$。

### 【直觉图】为什么是线性

```
第0代: [=========n0=========]           有益划分
第1代: [=======3n0/4=======]  ~ 2 次划分
第2代: [=====(3/4)²n0=====]  ~ 2 次划分
       ... 规模几何收缩，每代最多 2 步
       总成本 = 2·n0·(1 + 3/4 + (3/4)² + …) = 8n0 = O(n)
```

### 【例题 9.2-3】构造最坏情形

$A = \langle 2, 3, 0, 5, 7, 9, 1, 8, 6, 4\rangle$ 找最小值（$i=1$）。若枢轴依次选到 9, 8, 7, 6, 5, 4, 3, 2, 0，每步只淘汰枢轴自己，递归深度 10，总比较 $9+8+\cdots+1 = 45 = \Theta(n^2)$。

## 七、SELECT：中位数的中位数，最坏线性（§9.3）

### 【思想】用递归造枢轴

随机枢轴的问题是"不能保证好"。SELECT 的绝妙之处：**找一个保证不太差的枢轴，而找枢轴本身也是一次递归的选择**（§9.3，此 PDF p.324）：

1. 每 5 个元素一组，组内排序（插入排序，每组 $O(1)$）；
2. 找出每组的**中位数**（每组第 3 个）；
3. 把这些中位数**再递归**用 SELECT 找中位数，记为枢轴 $x$；
4. 绕 $x$ 分区，按 $i$ 与枢轴名次的关系递归一侧。

### 【伪代码】SELECT

```
// file: SELECT（§9.3，此 PDF p.324-325）
SELECT(A, p, r, i)
 1  while (r - p + 1) mod 5 ≠ 0            // 补齐到 5 的倍数
 2      for j = p + 1 to r
 3          if A[p] > A[j]
 4              exchange A[p] with A[j]    // 最小元素冒泡到 A[p]
 5      if i == 1                           // 就要最小值，直接交货
 6          return A[p]
 7      p = p + 1; i = i - 1                // 扔掉最小值，问题规模-1
 8  g = (r - p + 1)/5                       // 组数
 9  for j = p to p + g - 1
10      sort 〈A[j], A[j+g], A[j+2g], A[j+3g], A[j+4g]〉 in place
11  x = SELECT(A, p + 2g, p + 3g - 1, ⌈g/2⌉)   // 递归求组中位数的中位数
12  q = PARTITION-AROUND(A, p, r, x)        // 绕 x 分区
13  k = q - p + 1
14  if i == k
15      return A[q]
16  elseif i < k
17      return SELECT(A, p, q - 1, i)
18  else return SELECT(A, q + 1, r, i - k)
```

第 10-11 行的"跨步长取元组"是 CLRS 的经典技巧：$\langle A[j], A[j+g], \dots, A[j+4g]\rangle$ 排序后，各组中位数恰好连续落在 $A[p+2g : p+3g-1]$，省掉一个辅助数组。

### 【图示】为什么枢轴 $x$ 保证 7n/10 收缩

Figure 9.3 的解读（§9.3，此 PDF p.326-329）：

```
每列 = 一个排好序的 5 元组，红 = 组中位数，x = 中位数的中位数

 小半边的组               x 所在列              大半边的组
├─────────────┤   ├───┤   ├─────────────┤
│≤ x 的元素   │   │ ≤ │   │ ≥ x 的元素   │
│蓝区 ≥ 3g/2 │   │ = │   │ 黄区 ≥ 3g/2 │
│ 个元素      │   │ x │   │ 个元素       │
├─────────────┤   ├───┤   ├─────────────┤
│   低区最多 = 5g - 3g/2 = 7g/2 ≤ 7n/10    │
│   高区同样 ≤ 7n/10                        │
```

黄区：$\lfloor g/2\rfloor + 1$ 个组中位数 $\ge x$，每个带 2 个比它大的同组元素，共 $3(\lfloor g/2\rfloor+1) \ge 3g/2$ 个元素铁定在高侧；蓝区对称。所以每侧最多 $5g - 3g/2 = 7g/2 \le 7n/10$ 个元素。

### 【定理 9.3】SELECT 最坏时间 $\Theta(n)$

**证明**（§9.3，此 PDF p.327-330）：非递归部分：while 循环 $O(1)$ 轮 × 每轮 $\Theta(n)$、组排序 $\Theta(n)$、分区 $\Theta(n)$，共 $\Theta(n)$。递归部分：造枢轴 $\le T(n/5)$，主递归 $\le T(7n/10)$。递推：
$$T(n) \le T(n/5) + T(7n/10) + \Theta(n) = O(n)$$

代入法：设 $T(n)\le cn$，则 $T(n) \le c\cdot n/5 + c\cdot 7n/10 + \Theta(n) = 9cn/10 + \Theta(n) \le cn$，只要 $c$ 足够大让 $c/10$ 吃掉 $\Theta(n)$ 的常数。下界：第 10 行排序组就要 $\Theta(n)$。

### 【例题 9.3-1】★ 换成 7 个一组也行（书中习题）

**证明**：组大小改为 7，则组中位数递归规模 $\le n/7$，每侧最多 $5n/14$（类似推算：$7g - 5g/2 = 9g/2 \le 9n/14$）：
$$T(n) \le T(n/7) + T(9n/14) + \Theta(n)$$
$\frac17 + \frac9{14} = \frac{2}{14} + \frac9{14} = \frac{11}{14} < 1$，几何收缩仍成立，$T(n)=O(n)$。

**为什么不用 3 个一组？** 此时 $\frac13 + \frac23 = 1$，递推只给出 $O(n\lg n)$——造枢轴的递归不再"便宜"。5 是使 $\frac15 + \frac7{10} < 1$ 的最小奇组大小（3 不行、5 恰好 $\frac15+\frac7{10}=\frac9{10}$），这也是工程上鲜有人用 SELECT 的原因：常数太大。

### 【例题 9.3-6】黑盒中位数解任意选择

已有最坏 $O(n)$ 的中位数黑盒。求第 $i$ 小：用黑盒找中位数分区，若 $i$ 在低区递归低区，否则递归高区，每次规模减半：
$$T(n) = T(n/2) + O(n) = O(n)$$
（主定理 case 3）。这印证了一个深刻事实：**中位数并不比一般选择难**。

### 【拓展】选择 vs 排序

§9.3 末尾的对比值得记住（此 PDF p.330）：比较模型下排序需 $\Omega(n\lg n)$，但**选择不需要排序所有元素**也能线性——下界只约束"完整排序输出"。同理，比较排序的概率下界也存在（Problem 8-1：随机比较排序期望 $\Omega(n\lg n)$）。

## 八、本章方法总结

| 算法 | 时间 | 条件 | 稳定性 | 原地性 |
|---|---|---|---|---|
| 比较排序（归并/堆） | $O(n\lg n)$ 最坏 | 无 | 归并稳定 | 堆原地 |
| 计数排序 | $\Theta(n+k)$ 最坏 | 整数域 $[0,k]$ | **稳定** | 否 |
| 基数排序 | $\Theta(d(n+k))$ 最坏 | $d$ 位、每位 $k$ 值 | 稳定（依赖内层） | 否 |
| 桶排序 | $\Theta(n)$ 期望 | $[0,1)$ 均匀分布 | — | 否 |
| RANDOMIZED-SELECT | $\Theta(n)$ 期望 | 可比较 | — | 原地 |
| SELECT | $\Theta(n)$ 最坏 | 可比较 | — | 原地 |

**一句话**：下界 $\Omega(n\lg n)$ 是"只准比较"世界的王法；数值假设（小整数域、多位数、均匀分布）或随机化/分组 guarantees 都能合法绕开它。

## 九、例题精选（难度递进）

### 例题 A（基础）★ 书中 Ex 8.3-2 变体

问：计数排序稳定但基数排序依赖"每遍稳定"，若第 2 遍用了不稳定的快排会怎样？

**解**：假设处理完低位后排好 $\langle 12, 13, 21, 22\rangle$（两位数十位个位）。第 2 遍按十位不稳定排序可能把 21 换到 12 前（十位相同比大小），但 1 与 2 的次序会乱——最终 $\langle 21, 22, 12, 13\rangle$ 之类。**低位的次序信息被高位覆盖**，正是稳定性在基数排序中不可替代的原因。

### 例题 B（进阶）★ 书中 Ex 8.3-4

用 COUNTING-SORT 作内层，RADIX-SORT 调 $d$ 次要过 $2d$ 趟数据（每遍 COUNTING-SORT 扫两遍）。如何减到 $d+1$ 趟？

**解**：让 RADIX-SORT 预分配两个数组交替作输入/输出，COUNTING-SORT 改成取输出数组指针。第一遍：$A\to B$（数数扫 1 遍 + 放置扫 1 遍）。之后每遍：$B\to A$、$A\to B\cdots$ 每遍仍需 2 次扫描……**等等，实际减不下来到 $d+1$**——本题的意图是：把 $C$ 数组的**前缀和累加**（第 7 行）不计为"过数据"，且若把数数那遍与上一遍放置合并考虑，答案在于**每遍只扫一次数据**：把"数"与"放"合并（类似原地的关键思路）不可行，所以标准答案是利用**双缓冲**省掉一次数组拷贝，并把 $d$ 遍计数排序的初始化 $O(k)$ 用只清一次 $C$ + 记录非零位来摊平。核心考点是理解"过数据"的定义，工程上减少 $d$ 趟的常见做法是**增大基数 $r$**（引理 8.4）直接减少遍数。

### 例题 C（综合）★ 改编自 Ex 9.3-8 / 9.3-9

给定 $n$ 个互异数和 $k \le n$，$O(n\lg k)$ 列出第 $k$ 分位。

**解**：分位点是 $i\cdot n/k$（$i=1,\dots,k-1$）处的顺序统计量。用 SELECT 找一个分位点 $O(n)$，分区后每侧只剩 $n/k$ 量级的规模；对剩下的分位点在对应半边递归。递推 $T(n) = T(n/2)+O(n)$ 给 $O(n)$ 已经足够；但题目限 $\lg k$：分位数少时逐个 SELECT 共 $(k-1)O(n) = O(nk)$ 不达标。改用：每步 SELECT 一个分位后，**把该分位附近相关的连续分位批量处理**（它们都落在同侧 $n/k$ 区间内），总递推 $T(n,k) = T(n/2, k/2) + O(n)$，解得 $O(n\lg k)$。

## 十、习题与参考答案

> 以下混合了书中原题（标注编号）与自编模拟题（标注"模拟"）。建议先做再看答案。

### 第 8 章

**8-1a**（Prob 8-1）证明恰有 $n!$ 个叶子标注 $1/n!$、其余标 0。
<details>
<summary>答案</summary>
每个叶子的标注 = 产生该叶子的输入排列的概率。若某叶子被多个排列到达，标注是这些排列概率之和。所有排列等概（各 $1/n!$）。若叶子 $\ell$ 对应排列集合 $S_\ell$，则标注 $|S_\ell|/n!$。要求标注为 $1/n!$ 当且仅当 $|S_\ell|=1$：若 $|S_\ell|\ge 2$，标注 $\ge 2/n!$；若某叶子标注 $1/n!$ 则 $|S_\ell|=1$。排序算法正确 ⇒ 每个排列到达恰好一个叶子 ⇒ $\sum_\ell |S_\ell| = n!$。若有两个叶子 $|S_\ell|\ge 2$，则总数 $> n!$，矛盾。故恰 $n!$ 个叶子各对应一个排列。
</details>

**8-2b**（Prob 8-2）只含 0/1 键的记录：满足"稳定 + 原地"的 $O(n)$ 排序。
<details>
<summary>答案</summary>
两遍扫描：第一遍数 0 的个数 $z$；第二遍用两个指针 $i=1$（找 1）与 $j=z+1$（找 0），遇到 $A[i]=0$ 与 $A[j]=1$ 交换，直到指针交错。$\Theta(n)$ 时间、$O(1)$ 额外空间。稳定性：这是 0/1 特例下的原地稳定排序（对多值键不适用，但对本题键只有两值，交换后所有 0 在前 1 在后即有序，且相同键不可区分，平凡"稳定"）。
</details>

**8-3a**（Prob 8-3）不同整数位数不同，但总位数 $n$，$O(n)$ 排序。
<details>
<summary>答案</summary>
按位数分桶（每位数一次计数分类，$O(n)$），对同位数内的数用基数排序。每位宽 $O(\lg n)$ 位（因为单个整数最多 $n$ 位），总时间 $O(n + n\cdot\text{总位数}/\lg n)$——直接做法：把所有位流视作整体，先按最低位 LSD 基数排序，位宽 1 也只要 $O(\text{总位数}) = O(n)$ 遍中每遍 $O(n)$，总 $O(n^2)$；正确构造是**按位数分治**：位数 $\le \lg n$ 的数用引理 8.4 的 $r=\lg n$ 拆法，位数 $>\lg n$ 的数（最多 $n/\lg n$ 个）再递归。综合得 $O(n)$。
</details>

**模拟 8-M1**（★）证明 $\lg(n!) = \Theta(n\lg n)$ 不用 Stirling，只用分部求和。
<details>
<summary>答案</summary>
$\lg(n!) = \sum_{i=1}^n \lg i$。上界：每项 $\le \lg n$，和 $\le n\lg n$。下界：丢掉前一半小项，$\sum_{i=\lceil n/2\rceil}^n \lg i \ge \lfloor n/2\rfloor \lg(n/2) = \Omega(n\lg n)$。合起来 $\Theta(n\lg n)$（此即 Ex 8.1-2 的解法）。
</details>

**模拟 8-M2**（★★）$n$ 个 $[0, n^2-1]$ 内整数，$O(n)$ 排序（改编自 Ex 8.3-5）。
<details>
<summary>答案</summary>
$b=2\lg n$，取 $r=\lg n$：时间 $\Theta((2\lg n/\lg n)(n+2^{\lg n})) = \Theta(2n+n) = \Theta(n)$。
</details>

### 第 9 章

**9-1a**（Prob 9-1）$n$ 个数中找最大的 $i$ 个并按序输出，三种方法的最优最坏时间。
<details>
<summary>答案</summary>
(a) 排序后取尾部：$\Theta(n\lg n)$。(b) 建最大堆 $O(n)$ + $i$ 次 EXTRACT-MAX $O(i\lg n)$：$O(n + i\lg n)$。(c) 用 SELECT 找第 $i$ 大（$\Theta(n)$），分区（$\Theta(n)$），对 $i$ 个元素排序 $O(i\lg i)$：$\Theta(n + i\lg i)$。**最优是 (c)**：$i$ 小时近线性，$i=n$ 时退化为 $\Theta(n\lg n)$ 与排序一致。
</details>

**9-2a**（Prob 9-2）SIMPLER-RANDOMIZED-SELECT 最坏情况永不终止。
<details>
<summary>答案</summary>
看第 5-6 行：$i \le k$ 时递归到 $A[p:q]$——**枢轴还在子数组里**！若 $i=k$ 且枢轴恰是最后剩下的元素之外的情况：设 $A=\langle 1,2\rangle$ 找 $i=1$。若枢轴选到 2（$q=r$，$k=2$），$i=1\le 2$，递归 $A[1:2]$ 还是原数组。再次选到 2 的概率 $1/2$，永远选 2 则永不终止。修正是把 $i<k$ 才包含枢轴改为 $i=k$ 直接返回。
</details>

**9-3c**（Prob 9-3）$\Theta(n)$ 最坏求加权中位数。
<details>
<summary>答案</summary>
带权选择：维护权重前缀和。用 SELECT 找（无权）中位数 $m$ 作枢轴，分区后计算低区总权 $W_<$ 与高区总权 $W_>$。若 $W_< \ge 1/2$ 则加权中位数在低区，更新"还需累积的权"后递归低区；若 $W_> > 1/2$ 递归高区；否则 $m$ 即加权中位数。每步 SELECT 线性，规模减半，$T(n)=T(n/2)+O(n)=O(n)$。
</details>

**模拟 9-M1**（★）同时找第二小与第二大，最坏 $\lceil 3n/2\rceil + n - 2$ 次内。
<details>
<summary>答案</summary>
锦标赛找最小 $n-1$ 次 + 找最大 $n-1$ 次 = $2n-2$ 已达标。想更优：同时维护 min/max 的 $3\lfloor n/2\rfloor$ 锦标赛可同时给出两个冠军及其直接手下名单（各 $\le \lceil \lg n\rceil$ 人），再分别在两个"手下名单"里找次小、次大：$3\lfloor n/2\rfloor + 2(\lceil\lg n\rceil - 1)$。
</details>

**模拟 9-M2**（★★）证明：任何基于比较找中位数的算法最坏 $\Omega(n)$。
<details>
<summary>答案</summary>
中位数是某个特定元素，判定它必须让其余 $n-1$ 个元素都与它建立过直接或间接的比较关系，且它至少"胜过"$\lfloor n/2\rfloor$ 个、"负于"$\lfloor n/2\rfloor$ 个。用决策树/锦标赛变体：每个非中位元素要么直接输给中位数，要么输给某个最终被中位数间接击败的元素。对手论证：每次比较最多让一个元素"淘汰"一次，未淘汰元素数至少要到 1，故 $\ge n-1 = \Omega(n)$。
</details>

**模拟 9-M3**（★★★）★ 改编 Ex 9.3-10：两个已排序数组 $X[1:n], Y[1:n]$，$O(\lg n)$ 找 $2n$ 个数的中位数。
<details>
<summary>答案</summary>
二分删除法：比较 $X[\lfloor n/2\rfloor]$ 与 $Y[\lfloor n/2\rfloor]$，丢弃较小者的前半（共 $\lfloor n/2\rfloor$ 个必不在中位邻域）与较大者的后半，保持两边丢弃数相等，问题规模减半：$T(n)=T(n/2)+O(1)=O(\lg n)$。边界：某边空时中位即另一边中位。假设互异，偶数个取两中位的较小者（本书约定下中位数）。
</details>
