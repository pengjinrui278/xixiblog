## 一、动态集合的接口（Part III 引言）

算法操作的"集合"不是数学里静止的集合，而是会增删改的**动态集合**。典型操作：

| 操作 | 类型 | 说明 |
|---|---|---|
| SEARCH(S, k) | 查询 | 按键返回元素指针或 NIL |
| INSERT(S, x) | 修改 | 插入元素 $x$ |
| DELETE(S, x) | 修改 | **按指针**删除（不是按键！） |
| MINIMUM / MAXIMUM | 查询 | 全序集的最小/最大 |
| SUCCESSOR / PREDECESSOR | 查询 | 比 $x$ 大的下一个 / 比 $x$ 小的上一个 |

只支持 INSERT/DELETE/SEARCH 的又叫**字典**（此 PDF p.341-342）。

> **原文摘录**（Part III 引言，此 PDF p.342）
> "Of course, you can always choose to implement a dynamic set with an array. The advantage of doing so is that the algorithms for the dynamic-set operations are simple. The downside, however, is that many of these operations have a worst-case running time of $\Theta(n)$."

**数组实现的两种取舍**（此 PDF p.342）：
- **无序数组**：INSERT/DELETE 可以 $\Theta(1)$，其余查询 $\Theta(n)$；
- **有序数组**：MIN/MAX/SUCCESSOR/PREDECESSOR 全部 $\Theta(1)$、SEARCH 二分 $O(\lg n)$，但 INSERT/DELETE 最坏 $\Theta(n)$（要搬元素）。

第 12-13 章的红黑树能做到"全都 $O(\lg n)$"，本篇的散列则用概率换"全都期望 $O(1)$"。

## 二、数组与矩阵：地址即公式（§10.1）

### 【定义】数组的内存公式

> **原文摘录**（§10.1.1，此 PDF p.344）
> "If the first element of an array has index $s$, the array starts at memory address $a$, and each array element occupies $b$ bytes, then the $i$th element occupies bytes $a + b(i-s)$ through $a + b(i-s+1) - 1$."

在 RAM 模型下访问任意元素 $O(1)$——这条性质是后面一切"按下标随机跳转"算法（堆、计数排序、散列）的地基。元素大小不一时，数组里存的是**指针**，跟一次指针才到对象（此 PDF p.344-345）。

### 矩阵的两种存法

$m\times n$ 矩阵存进一维数组（此 PDF p.345-346）：

| 方式 | 公式（下标从 $s$ 起） | $s=0$ 时 |
|---|---|---|
| 行主序 | $s + n(i-s) + (j-s)$ | $ni + j$ |
| 列主序 | $s + m(j-s) + (i-s)$ | $i + mj$ |

**行主序**：一行挨一行；**列主序**：一列挨一列。例：$M[2,1]$（1-origin）在行主序单数组中位于下标 $3(2-1)+1=4$，列主序位于 $2+2(1-1)=2$（此 PDF p.346）。

> **工程提示**：单数组表示通常比"每行一个数组 + 指针数组"更快（局部性好）；多数组表示支持**参差数组**（各行长度不同）。

## 三、栈与队列：带属性的数组（§10.1.3）

### 栈：LIFO

属性 $S.top$（指向最近插入）与 $S.size$（数组容量）。$S.top=0$ 表示空；$S.top=S.size$ 还 push 就**上溢**；空栈 pop 是**下溢**（此 PDF p.347-348）。三个操作都 $O(1)$：

```
STACK-EMPTY(S)
 1  if S.top == 0
 2      return TRUE
 3  else return FALSE

PUSH(S, x)
 1  if S.top == S.size
 2      error "overflow"
 3  else S.top = S.top + 1
 4          S[S.top] = x

POP(S)
 1  if STACK-EMPTY(S)
 2      error "underflow"
 3  else S.top = S.top - 1
 4          return S[S.top + 1]
```

### 队列：FIFO 与环形缓冲区

队列有头尾属性，用**循环数组**实现：存 $n-1$ 个元素（$Q.head = Q.tail$ 为空；$Q.head = Q.tail+1$ 为满，此 PDF p.349-350）。ENQUEUE 写到 $Q.tail$ 再前移，DEQUEUE 读 $Q.head$ 再前移，都 $O(1)$：

```
ENQUEUE(Q, x)
 1  Q[Q.tail] = x
 2  if Q.tail == Q.size
 3      Q.tail = 1          // 绕回
 4  else Q.tail = Q.tail + 1

DEQUEUE(Q)
 1  x = Q[Q.head]
 2  if Q.head == Q.size
 3      Q.head = 1
 4  else Q.head = Q.head + 1
 5  return x
```

**为什么只能放 $n-1$ 个**：若允许 $n$ 个，则"满"时也有 $Q.head = Q.tail$，与"空"无法区分。要么牺牲一格，要么额外计数器。

## 四、链表：指针织出的线性序（§10.2）

### 【定义】双向链表

> **原文摘录**（§10.2，此 PDF p.352）
> "A linked list is a data structure in which the objects are arranged in a linear order. Unlike an array, however, in which the linear order is determined by the array indices, the order in a linked list is determined by a pointer in each object."

每个元素有 `key`、`next`、`prev`。$x.prev = \text{NIL}$ 是头，$x.next=\text{NIL}$ 是尾，$L.head$ 指向首元素。单链表只有 next；循环链表头尾互指；还有有序/无序之分。

### 操作与复杂度

| 操作 | 双向链表 | 数组对照 |
|---|---|---|
| LIST-SEARCH(L,k) | $\Theta(n)$ | 无序 $\Theta(n)$ / 有序 $O(\lg n)$ |
| LIST-PREPEND(L,x) | $O(1)$ | 头插 $\Theta(n)$（全部后移） |
| LIST-INSERT(x,y)（插到 $y$ 后） | $O(1)$ | $\Theta(n)$ |
| LIST-DELETE(L,x)（已知指针） | $O(1)$ | $\Theta(n)$ |
| 按键删除 | $\Theta(n)$（含 SEARCH） | 有序 $\Theta(n)$ |
| 取第 $k$ 个 | $\Theta(k)$ | $O(1)$ |

**链表赢在"局部修改"，数组赢在"随机访问"**（此 PDF p.355）。

### 【技巧】哨兵：消灭边界条件

> **原文摘录**（§10.2，此 PDF p.356）
> "A sentinel is a dummy object that allows us to simplify boundary conditions."

用对象 $L.nil$ 代替 NIL：空表就是哨兵自指（$L.nil.next = L.nil.prev = L.nil$），LIST-DELETE 缩成两行且无需判断头尾：

```
LIST-DELETE′(x)                 LIST-INSERT′(x, y)
 1  x.prev.next = x.next          1  x.next = y.next
 2  x.next.prev = x.prev          2  x.prev = y
                                3  y.next.prev = x
                                4  y.next = x
```

哨兵的另一个妙用是 LIST-SEARCH′：先把要找的键 $k$ **写进哨兵**，搜索必然在哨inel 处停下，省去每轮的越界检查（此 PDF p.357-358）：

```
LIST-SEARCH′(L, k)
 1  L.nil.key = k          // 保证 k 一定"在"表中
 2  x = L.nil.next
 3  while x.key ≠ k
 4      x = x.next
 5  if x == L.nil          // 停在哨兵 ⇒ 真的不在
 6      return NIL
 7  else return x
```

代价：每个小链表都浪费一个哨兵的空间。CLRS 的原则——**只在显著简化代码时用哨兵**。

### ★【拓展】异或链表（Ex 10.2-6）

每个节点只存 $x.np = x.next \oplus x.prev$，遍历时用前一个节点的地址异或还原下一个：$next = np \oplus prev$。空间省一半指针，且**反转整个链表只要交换头尾指针** $O(1)$。工程上基本没人用——调试困难、GC 不友好。

## 五、有根树的表示（§10.3）

### 二叉树

节点属性 `p`（父）、`left`、`right`。$x.p=\text{NIL}$ ⇒ $x$ 是根；$T.root=\text{NIL}$ ⇒ 空树（此 PDF p.360）。

### 【技巧】左孩子右兄弟表示

孩子数不定时，分配固定个 child 属性会浪费。经典解法：每个节点只存两个指针（此 PDF p.360）：

- $x.left\text{-}child$：指向最左孩子；
- $x.right\text{-}sibling$：指向右边兄弟。

```
       A                      A
    /  |  \                 /
   B   C   D      ⇒       B — C — D
  / \                    / \
 E   F                  E   F
（任意度数树）        （每个节点 3 指针：p + left-child + right-sibling）
```

任意 $n$ 节点树只用 $O(n)$ 空间。找父 $O(1)$；枚举所有孩子 $O(\text{孩子数})$（顺着 right-sibling 走）。

### 其他表示（此 PDF p.362）

- **堆**（第 6 章）：完全二叉树 → 单数组 + 末节点下标，无指针；
- **第 19 章**：只往根走，只存父指针，孩子指针全省了；
- **启示**：表示方案跟着**访问模式**走，没有万能表示。

## 六、从直接寻址到散列（§11.1-11.2）

### 【定义】直接寻址表

若键的全域 $U=\{0,1,\dots,m-1\}$ 不大，直接开一个大小为 $|U|$ 的数组 $T$，$T[k]$ 就是键 $k$ 的元素。三个操作都 $O(1)$ **最坏**：

```
DIRECT-ADDRESS-SEARCH(T, k)     DIRECT-ADDRESS-INSERT(T, x)
 1  return T[k]                    1  T[x.key] = x

                               DIRECT-ADDRESS-DELETE(T, x)
                                   1  T[x.key] = NIL
```

**痛点**：$|U|$ 巨大而实际存储的键集 $K$ 很小时，空间全浪费。

### 【定义】散列表与散列函数

> **原文摘录**（§11.2，此 PDF p.372）
> "With direct addressing, an element with key $k$ is stored in slot $k$, but with hashing, we use a hash function $h$ to compute the slot number from the key $k$, so that the element goes into slot $h(k)$."

$h: U \to \{0,1,\dots,m-1\}$，$m \ll |U|$。因为 $|U|>m$，鸽笼原理保证**冲突（collision）不可避免**，于是有两类解法：**链接法**（冲突元素挂成链表）与**开放寻址**（在表内另找位置）。

### 【定义】负载因子

$$\alpha = n/m$$

散列分析的全部复杂性都浓缩在这个比值里。

### 链接法（chaining）

槽 $j$ 指向一个链表，装着所有 $h(k)=j$ 的元素。操作极简：

```
CHAINED-HASH-INSERT(T, x)
 1  LIST-PREPEND(T[h(x.key)], x)     // 头插，O(1) 最坏

CHAINED-HASH-SEARCH(T, k)
 1  return LIST-SEARCH(T[h(k)], k)   // 链表线性查找

CHAINED-HASH-DELETE(T, x)
 1  LIST-DELETE(T[h(x.key)], x)      // 已知指针，O(1)
```

插入 $O(1)$ 最坏（假定 $x$ 不在表中）；删除用**双向链表**才 $O(1)$（单链表要先找到前驱，$\Theta(n)$）。

### 【分析】$\Theta(1+\alpha)$：链接法的全部理论

假设**独立均匀散列**（independent uniform hashing）：每个键等概落入任一槽，且各键落点独立（此 PDF p.376）。

> **定理 11.1**：不成功查找平均 $\Theta(1+\alpha)$。
> **证明**：未存储的键等概散到任一槽，期望扫完长度 $E[n_{h(k)}]=\alpha$ 的链表，加算 $h(k)$ 的 $O(1)$。

> **定理 11.2**：成功查找平均也是 $\Theta(1+\alpha)$——但证明微妙得多。

**为什么成功查找不能也用 $\alpha$ 一句话打发**：不成功查找等概落到任一槽（含空槽）；成功查找**不会**落到空槽，且**长链表被找到的概率更大**——要找的元素等概是 $n$ 个元素中的任一个，表越长越可能被搜到。这个"大小偏倚"必须处理。

**CLRS 的证明（指示器变量教科书范例，此 PDF p.377-379）**：

1. 新元素**头插**进链表 ⇒ 元素 $x_i$ 之前的元素都是比它**晚插入**的。设 $x_i$ 是第 $i$ 个插入的。
2. 对每对 $(i,j)$（$i<j$）和每个槽 $q$，定义 $X_{ijq} = I\{\text{搜的是 }x_i,\ h(k_i)=q,\ h(k_j)=q\}$。三事件独立：
$$\Pr\{X_{ijq}=1\} = \frac1n\cdot\frac1m\cdot\frac1m = \frac{1}{nm^2}$$
3. 定义 $Y_j = I\{x_j \text{ 在链表里排在被搜元素之前}\} = \sum_{q}\sum_{i<j} X_{ijq}$（每个 $j$ 至多被一个 $X$ 计入）。
4. 被搜元素前面共有 $Z=\sum_j Y_j$ 个元素，扫描数 = $Z+1$。
5. 期望线性性：
$$E[Z+1] = 1 + \sum_j E[Y_j] = 1 + \sum_{j}\sum_{i<j}\sum_q \frac{1}{nm^2} = 1 + \frac{1}{nm^2}\cdot\frac{n(n-1)}{2}\cdot m = 1 + \frac{n-1}{2m} = 1 + \frac{\alpha}{2} - \frac{\alpha}{2n}$$

即 $\Theta(1+\alpha)$。**注意常数只有 $\alpha/2$ 而不是 $\alpha$**——头插 + 插入顺序的巧妙让成功查找比不成功还快约一半。

**推论**：$n=O(m)$（$\alpha=O(1)$）时所有字典操作期望 $O(1)$。这就是 Java HashMap、Python dict 的立论根基。

### 【例题 11.2-1】期望冲突数

$n$ 个键散到 $m$ 槽，冲突对（同槽的不同键对）的期望基数？

**解**：每对键冲突概率 $1/m$，共 $\binom{n}{2}$ 对，期望 $\binom{n}{2}/m = n(n-1)/(2m)$（期望线性性，无需独立！）。

### 【例题 11.2-2】逐步演算链接法

$m=9$，$h(k)=k\bmod 9$，依次插入 $5, 28, 19, 15, 20, 33, 12, 17, 10$：

| 键 | $h(k)$ | 槽内链表（头→尾） |
|---|---|---|
| 5 | 5 | 5 |
| 28 | 1 | 28 |
| 19 | 1 | 19 → 28 |
| 15 | 6 | 15 |
| 20 | 2 | 20 |
| 33 | 6 | 33 → 15 |
| 12 | 3 | 12 |
| 17 | 8 | 17 |
| 10 | 1 | 10 → 19 → 28 |

注意 33 头插到 15 前面——这正是定理 11.2 证明依赖的细节。

## 七、散列函数的设计（§11.3）

### 静态散列：除法与乘法

**除法**：$h(k) = k \bmod m$。一次除法，快。经验法则：$m$ 取**不太接近 2 的幂的素数**（此 PDF p.383）。

**乘法**：$h(k) = \lfloor m(kA \bmod 1)\rfloor$，$0<A<1$。优点：$m$ 的取值不挑剔。

**乘法-移位（multiply-shift）**：$m=2^\ell$ 时的特例。取定 $w$ 位奇数 $a$，$h_a(k) = (ka \bmod 2^w) \gg (w-\ell)$——乘、截断、移位三条指令（此 PDF p.383-384）。例：$k=123456, \ell=14, a=2654435769$（Knuth 推荐），得 $h_a(k)=67$。

> 静态散列的死穴：**对手可以针对已知 $h$ 构造 $n$ 个全落同一槽的键**，检索退化 $\Theta(n)$（此 PDF p.385）。

### 【定义】通用散列函数族（universal family）

> **原文摘录**（§11.3.2，此 PDF p.385）
> "The only effective way to improve the situation is to choose the hash function randomly in a way that is independent of the keys that are actually going to be stored."

族 $\mathcal{H}$ 称为**通用**，若任意两个不同键 $k_1\ne k_2$，$\mathcal{H}$ 中使它们冲突的函数至多 $|\mathcal{H}|/m$ 个，即
$$\Pr_{h\in\mathcal{H}}\{h(k_1)=h(k_2)\} \le \frac1m$$

——随机选一个 $h$，任意两键冲突概率不超过"真随机"的 $1/m$。**随机化的角色**（此 PDF p.385）：好性能不再依赖"输入键的分布未知而恰好均匀"，而依赖"我们自己的抛硬币"。

### 【定理 11.4】数论构造的通用族

选素数 $p$ 覆盖所有键（$p>m$），定义
$$h_{a,b}(k) = \big((ak + b) \bmod p\big) \bmod m,\qquad a\in\{1,\dots,p-1\},\ b\in\mathbb{Z}_p$$

$\mathcal{H}_{p,m}=\{h_{a,b}\}$ 共 $p(p-1)$ 个函数，**通用**（此 PDF p.388-390）。

**证明骨架**：
1. $r_1 - r_2 = a(k_1-k_2)\pmod p$；$p$ 素、$a\ne 0$、$k_1\ne k_2$ ⇒ 乘积非零 ⇒ $r_1\ne r_2$。"mod $p$ 层"零冲突。
2. $(a,b)$ 与 $(r_1,r_2)$ 一一对应（由 $r_1,r_2$ 解出 $a,b$）⇒ 随机 $(a,b)$ 等价于随机**互异**的 $(r_1,r_2)$。
3. 固定 $r_1$ 后，$p-1$ 个候选 $r_2$ 中与 $r_1$ 模 $m$ 同余的最多 $(p-1)/m$ 个 ⇒ 冲突概率 $\le \frac{(p-1)/m}{p-1} = \frac1m$。

### 【定理 11.5】乘法-移位的通用族（实践推荐）

$a$ 取**随机奇数**：
$$h_a(k) = \big((ka) \bmod 2^w\big) \gg (w-\ell)$$

$\mathcal{H}$ 是 **$2/m$-通用**的：冲突概率 $\le 2/m$（此 PDF p.390-391）。冲突概率翻倍，但换来实现极快，实践上 CLRS **推荐这个**。

### 长输入（字符串/向量）

- 数论路线：把串当 radix-128 数，**边读边取模**（$h = (h\cdot 128 + c)\bmod m$），常数空间（Ex 11.3-2）；
- 密码学路线：$h(k) = \text{SHA-256}(k)\bmod m$，加盐做族：$h_a(k)=\text{SHA-256}(a\|k)\bmod m$（此 PDF p.392）。

### 【性质阶梯】§11.3.3 速查

| 性质 | 条件 |
|---|---|
| uniform（均匀） | $\Pr\{h(k)=q\}=1/m$ 对一切 $k,q$ |
| universal（通用） | $\Pr\{h(k_1)=h(k_2)\}\le 1/m$ |
| $\epsilon$-universal | $\Pr\{\text{冲突}\}\le\epsilon$ |
| $d$-independent | 任意 $d$ 个键独立均匀落入指定槽，概率 $1/m^d$ |

通用 $\Rightarrow$ 分析只需"两两冲突 $\le 1/m$"这一条（推论 11.3：$n=O(m)$ 时，任意 $s$ 个操作的序列总期望 $\Theta(s)$，**对手再也不能逼出最坏**，此 PDF p.395-396）。

## 八、开放寻址：不存指针，全靠探测（§11.4）

### 【定义】开放寻址

> **原文摘录**（§11.4，此 PDF p.394）
> "In open addressing, all elements occupy the hash table itself. That is, each table entry contains either an element of the dynamic set or NIL."

所有元素存在表内，每槽要么是元素要么是 NIL。于是 $\alpha \le 1$（表会满）。散列函数带上探测序号：
$$h: U\times\{0,1,\dots,m-1\}\to\{0,\dots,m-1\}$$
要求每个键的探测序列 $\langle h(k,0),\dots,h(k,m-1)\rangle$ 是 $\langle 0,\dots,m-1\rangle$ 的**排列**（迟早扫遍全表）。

```
HASH-INSERT(T, k)                    HASH-SEARCH(T, k)
 1  i = 0                              1  i = 0
 2  repeat                             2  repeat
 3      q = h(k, i)                    3      q = h(k, i)
 4      if T[q] == NIL                 4      if T[q] == k
 5          T[q] = k; return q         5          return q
 6      else i = i + 1                 6      i = i + 1
 7  until i == m                       7  until T[q] == NIL or i == m
 8  error "hash table overflow"        8  return NIL
```

### 删除的坑与 DELETED 标记

删掉槽 $q$ 的元素后若直接置 NIL，会**切断其他键的探测链**（那些键当年探测时 $q$ 是被占的）。标准解法：置特殊值 DELETED——INSERT 视之为空，SEARCH 越过它。代价：搜索时间不再只由 $\alpha$ 决定。所以**需要频繁删除时选链接法**（此 PDF p.396）。

### 双散列（double hashing）

$$h(k,i) = \big(h_1(k) + i\cdot h_2(k)\big) \bmod m$$

起始位置 $h_1(k)$、步长 $h_2(k)$，产生 $\Theta(m^2)$ 条不同探测序列，接近理想。要求 $h_2(k)$ 与 $m$ **互质**才能扫遍全表（Ex 11.4-5：若 $\gcd = d$，只能看 $1/d$ 的表）。常用做法：$m$ 取 2 的幂且 $h_2$ 恒产出奇数；或 $m$ 素数且 $h_2(k)=1+(k\bmod m')$，$m'$ 略小于 $m$（此 PDF p.397-398）。

### 线性探查（linear probing）

双散列的特例 $h_2(k)\equiv 1$：$h(k,i)=(h_1(k)+i)\bmod m$。只有 $m$ 条探测序列，但**实现最简单、缓存最友好**。经典例子（此 PDF p.397）：$m=13$，$h_1(k)=k\bmod 13$，$h_2(k)=1+(k\bmod 11)$，键 14：$h_1=1$、$h_2=3$，探测 1、5、9，落入空槽 9。

### 【分析】$1/(1-\alpha)$：开放寻址的全部理论

假设**独立均匀排列散列**：每键的探测序列等概是 $m!$ 个排列中的任一个（此 PDF p.399-400）。

> **定理 11.6**：不成功查找期望探测数 $\le \dfrac{1}{1-\alpha} = 1+\alpha+\alpha^2+\cdots$（$\alpha<1$）。

**证明（尾概率公式的漂亮应用）**：设 $A_i$ = "第 $i$ 次探测发生且撞到已占槽"。则
$$\Pr\{X\ge i\} = \Pr\{A_1\cap\cdots\cap A_{i-1}\} = \prod_{j=1}^{i-1}\frac{n-j+1}{m-j+1} \le \left(\frac nm\right)^{i-1} = \alpha^{i-1}$$

（关键一步：$n<m$ 时 $\frac{n-j}{m-j}\le\frac nm$。）再用 $E[X]=\sum_{i\ge1}\Pr\{X\ge i\}$（公式 C.28）：
$$E[X] \le \sum_{i\ge1}\alpha^{i-1} = \frac{1}{1-\alpha}$$

**直觉**：第一次探测必然发生；以约 $\alpha$ 概率第一次撞上、发生第二次；以约 $\alpha^2$ 概率前两次都撞上……几何级数求和。

> **推论 11.7**：INSERT 的期望探测数同样 $\le 1/(1-\alpha)$（插入 = 一次不成功查找 + 放置）。

> **定理 11.8**：成功查找期望探测数 $\le \dfrac1\alpha\ln\dfrac{1}{1-\alpha}$。

**证明**：第 $i+1$ 个插入的键，插入时负载因子是 $i/m$，查找它期望探测 $1/(1-i/m)=m/(m-i)$。对 $n$ 个键取平均：
$$\frac1n\sum_{i=0}^{n-1}\frac{m}{m-i} = \frac{m}{n}\sum_{i=0}^{n-1}\frac{1}{m-i} = \frac1\alpha\big(H_m - H_{m-n}\big) \le \frac1\alpha\ln\frac{1}{1-\alpha}$$

**数字直觉**（此 PDF p.403）：

| $\alpha$ | 不成功 | 成功 |
|---|---|---|
| 1/2 | $\le 2$ | $< 1.387$ |
| 9/10 | $\le 10$ | $< 2.559$ |
| $\to 1$ | $\to\infty$ | $\to H_m \approx \ln m$ |

**开放寻址对满表极度敏感**——90% 满时不成功查找要 10 次探测，这就是工程上要把 $\alpha$ 压在 0.5~0.75 的原因。

### 线性探查的聚集效应与工程反转

**一次群集（primary clustering）**：空槽前若有 $i$ 个连续占槽，它被填的概率是 $(i+1)/m$——长簇更容易变长，平均搜索时间恶化（此 PDF p.407-408）。

> **定理 11.9**（Pagh 等）：$h_1$ 是 **5-独立**且 $\alpha\le 2/3$ 时，线性探查的查找/插入/删除期望 $O(1)$。

**第 4 版的工程洞见**（此 PDF p.405-408）：RAM 模型里线性探查因群集被嫌弃，但**层级内存模型**里群集是优点——连续探测大概率命中同一缓存块。于是现代高性能散列表的配方是：**复杂但寄存器内可算的散列函数（如 wee hash，基于 RC6 思想：乘方 + 交换半字，4 轮）+ 线性探查**。实测：算一次 wee hash 比随机探一次槽还快 2~10 倍（此 PDF p.409-410）。

### 线性探查的免标记删除

§11.5.1 给出一个精巧办法：定义反函数 $g(k,q) = (q - h_1(k))\bmod m$（槽 $q$ 在键 $k$ 的探测序列中是第几步）。删除槽 $q$ 的键 $k$ 后向后扫描：若某键 $k'$ 满足 $g(k',q) < g(k',q')$（说明 $k'$ 插入时 $q$ 是被占的、现在空了），把 $k'$ 挪到 $q$，继续处理 $q'$（此 PDF p.406-407）：

```
LINEAR-PROBING-HASH-DELETE(T, q)
 1  while TRUE
 2      T[q] = NIL            // 腾空 q
 3      q′ = q
 4      repeat
 5          q′ = (q′ + 1) mod m
 6          k′ = T[q′]
 7          if k′ == NIL
 8              return        // 遇到空槽，链条完整
 9      until g(k′, q) < g(k′, q′)   // q 是否被 k′ 探测过？
10      T[q] = k′             // 挪过来
11      q = q′                // 继续处理新空位
```

例（此 PDF p.407）：插 74, 43, 93, 18, 82, 38, 92（$h_1=k\bmod 10$）后，删 43：93 上移到 43 的槽，92 再上移到 93 腾出的槽——链不断。

### 【拓展】完美散列（第 3 版 §11.5，第 4 版已删）

静态键集合可做到 $O(1)$ **最坏**查找：先用一级通用散列 + 链接；再对每个槽内的链表，用二级散列（空间二次于表长）实现零冲突。总空间 $O(n)$，构建期望 $O(n)$。思想源头仍是 Carter-Wegman 通用散列；现代变体见 FKS 完美散列与最小完美散列（MPH，用于静态字典/数据库索引）。

## 九、两种冲突解决方案对照

| 维度 | 链接法 | 开放寻址 |
|---|---|---|
| 存储 | 表外链表 | 全在表内，无指针 |
| $\alpha$ | 可 $>1$ | 必 $\le 1$ |
| 期望时间（$\alpha=O(1)$） | $\Theta(1+\alpha)$ | 不成功 $1/(1-\alpha)$ |
| 删除 | 双向链表 $O(1)$ | 需 DELETED 标记（或线性探查特例） |
| 缓存友好 | 差（指针跳转） | 好（线性探查尤佳） |
| 适用 | 通用、频繁删 | 内存敏感、缓存敏感 |

## 十、例题精选（难度递进）

### 例题 A（基础）★ Ex 11.1-2

用位向量表示 $\{0,\dots,m-1\}$ 上无卫星数据的动态集合，$O(1)$ 操作。

**解**：$m$ 位数组，键 $k$ 在表中 $\Leftrightarrow$ 第 $k$ 位为 1。INSERT 置位、DELETE 清位、SEARCH 读位，都 $O(1)$；空间比指针数组省 $\Theta(w)$ 倍。

### 例题 B（进阶）★ Ex 11.2-3

Marley 教授想让每条链表**保持有序**。四种操作怎么变？

**解**：成功查找不变（还是要扫到目标，$\Theta(1+\alpha)$）；**不成功查找可以提前退出**（扫到比 $k$ 大的就可停），平均略快；插入从 $O(1)$ 变 $O(\text{表长})$；删除（已知指针）仍 $O(1)$（双向链表）但保持有序要重新插入，$\Theta(1+\alpha)$。总结：**用插入和删除变慢，换不成功查找小幅变快**，通常不划算——除非不成功查找占绝对多数。

### 例题 C（综合）★ Ex 11.4-3

开放寻址，$\alpha=3/4$ 与 $7/8$ 时的探测数上界。

**解**：不成功：$1/(1-3/4)=4$；$1/(1-7/8)=8$。成功：$\frac1{0.75}\ln\frac{1}{0.25}=\frac43\ln4\approx1.85$；$\frac1{0.875}\ln 8 = \frac87\cdot 2.079 \approx 2.38$。

### 例题 D（综合）★ Ex 11.2-5 改编

$|U|>(n-1)m$ 时，证明存在 $n$ 个键全落同一槽，链接法最坏 $\Theta(n)$。

**解**：反证。若每个槽最多 $n-1$ 个键落入，则 $|U|\le m(n-1)$，矛盾。所以某槽被至少 $n$ 个键共享。**教训**：任何**固定**散列函数都有灾难集；这正是要随机化散列函数族的动机。

|---|---|---|---|---|
| SEARCH | $\Theta(n)$ | $\Theta(n)$（可提前停） | $\Theta(n)$ | $\Theta(n)$（可提前停） |

**10.2-5**（★）$\Theta(n)$ 非递归反转单链表，常数额外空间。
<details>
<summary>答案</summary>
三指针滚动：`prev = NIL; cur = head; while cur ≠ NIL: next = cur.next; cur.next = prev; prev = cur; cur = next; head = prev`。每节点 $O(1)$，共 $\Theta(n)$，只用三个指针。
</details>

**模拟 10-M1**（★）两个栈共享一个数组 $A[1:n]$，都不溢出除非总数 $n$。
<details>
<summary>答案</summary>
栈 1 从 1 向上长（top1 初 0），栈 2 从 $n$ 向下长（top2 初 $n+1$）。PUSH1：`if top1+1 == top2: overflow; top1++; A[top1]=x`；PUSH2 对称。两栈相接才满，各自有 $\Theta(n)$ 容量。POP 判断对应栈空。所有操作 $O(1)$。
</details>

**模拟 10-M2**（★★）用两个栈实现队列，分析操作时间。
<details>
<summary>答案</summary>
in-stack 收 ENQUEUE（PUSH 进）；DEQUEUE 时若 out-stack 空，把 in-stack 全部倒灌进 out-stack（顺序自然颠倒成正序），再 POP。摊还分析：每元素进 in 一次、倒一次、出 out 一次，三次 $O(1)$ ⇒ **摊还 $O(1)$/操作**。单次操作最坏 $O(n)$（倒灌那一刻）。
</details>

### 第 11 章

**11-2b**（Prob 11-2）开放寻址要做到不成功查找平均不差于二分 $O(\lg n)$，至少要多大的 $m-n$？
<details>
<summary>答案</summary>
$\frac{1}{1-\alpha}\le c\lg n$ ⇒ $1-\alpha \ge \frac{1}{c\lg n}$ ⇒ $m-n \ge \frac{n}{c\lg n} = \Theta(n/\lg n)$。即**空槽数至少与 $n/\lg n$ 同阶**——常驻负载因子 $\alpha = 1-\Theta(1/\lg n)$。
</details>

**11-4a**（Prob 11-4）2-独立 ⇒ 通用。
<details>
<summary>答案</summary>
2-独立：任意两不同键落入指定两槽的概率 $1/m^2$。固定 $k_1,k_2$，冲突概率 $=\sum_q \Pr\{h(k_1)=q,h(k_2)=q\} = m\cdot\frac1{m^2} = \frac1m$。正是通用的定义。
</details>

**11-4d**（Prob 11-4）2-独立族做认证标签，敌手欺骗成功率 $\le 1/p$。
<details>
<summary>答案</summary>
$h$ 从 2-独立族秘密随机选取。敌手见到 $(m,t)$ 后任选 $m'\ne m$、任算 $t'$（计算能力无限、知道族 $\mathcal{H}$ 也不知道 $h$）。$\Pr\{h(m')=t'\}\le 1/p$ 对一切 $m',t'$ 成立——正是 2-独立（$h(m)$ 均匀 + 与 $h(m')$ 独立）的直接后果。这就是一次性消息认证码（MAC）信息论安全的原型。
</details>

**模拟 11-M1**（★）证明 $\lg(n!)$ 之外：$\binom{n}{2}/m$ 的期望冲突数推导中"不需要独立性"。
<details>
<summary>答案</summary>
期望线性性对任意随机变量成立（无需独立）。$X=\sum_{\text{键对}}\mathbf{1}\{\text{该对冲突}\}$，$E[X]=\sum E[\mathbf{1}]=\sum\Pr\{\text{冲突}\}$，只用到每对冲突概率 $1/m$。
</details>

**模拟 11-M2**（★★）开放寻址 $\alpha=1-\frac1k$ 时，不成功查找期望探测数的渐近。
<details>
<summary>答案</summary>
$\frac{1}{1-\alpha}=k$。即空槽每少 $1/k$，探测数涨 $k$ 倍——$\alpha\to1$ 时**急剧**劣化（对比链接法的 $\Theta(1+\alpha)$ 只是温和线性增长）。工程含义：开放寻址必须在 $\alpha$ 冲到高位之前扩容。
</details>

**模拟 11-M3**（★★★）设计：字典要支持 $10^7$ 次/秒查找、频繁插入删除、键为 64 位整数、内存吃紧。选方案并论证。
<details>
<summary>答案</summary>
选**开放寻址 + 双散列**（或缓存友好场景下的线性探查 + 5-独立散列）。理由：(1) 无指针，同内存下槽更多、$\alpha$ 更低、探测更少；(2) 频繁插入删除——开放寻址的 DELETED 标记会使搜索时间劣化，若删除极频繁应回到链接法或用墓碑压缩；(3) 64 位整数可直接用乘法-移位族（随机奇数 $a$），三条指令出散列值；(4) 内存吃紧 ⇒ 省掉每元素的 next/prev 指针是最大红利。若删除占到操作 1/3 以上，则链接法 + 双向链表 + $\alpha\le 1$ 更稳。
</details>
